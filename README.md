# stellar-vesting

[![CI](https://github.com/Alimzy/stellar-vesting/actions/workflows/ci.yml/badge.svg)](https://github.com/Alimzy/stellar-vesting/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Linear token vesting with a cliff and optional revocation, for **any SEP-41 token** on
[Soroban](https://developers.stellar.org/docs/build/smart-contracts/overview).
One deployed contract holds any number of fully isolated schedules, so a team, a DAO or a
grants program can vest to many people from a single contract ID.

- **Cliff + linear release.** Nothing before the cliff; from the cliff on, tokens unlock
  continuously until the end date.
- **Revocable or locked.** The funder chooses at creation. Revoking returns only the
  *unvested* part; what already vested stays claimable by the beneficiary.
- **Pull-based claims.** The beneficiary claims whenever they like; no keeper needed.
- **Many schedules, one contract.** Every schedule has its own funder, beneficiary, token and
  timeline. Accounting is per schedule.
- **Storage-lifetime safe.** Every state-changing entrypoint extends instance and schedule TTL,
  and anyone can call `bump` to keep a long schedule alive.
- **Typed errors and events.** Stable error codes; `ScheduleCreated`, `Claimed`, `Revoked`
  events for indexers.

> Status: implemented and tested (22 tests, including property tests). Testnet deployment proof
> is generated by `scripts/demo-testnet.sh`; see [FEATURE-STATUS.md](FEATURE-STATUS.md) for what
> has and has not been verified.

## Contract API

| Function | Auth | What it does |
|---|---|---|
| `create_schedule(funder, beneficiary, token, amount, start, cliff, end, revocable) -> u64` | funder | Locks `amount` and returns the schedule id |
| `claim(id) -> i128` | beneficiary | Pays out everything vested and unclaimed |
| `revoke(id) -> i128` | funder | Refunds the unvested remainder (revocable schedules only) |
| `bump(id)` | none | Extends contract and schedule storage lifetime |
| `vested_amount(id) -> i128` | none | Total vested so far (claimed or not) |
| `claimable(id) -> i128` | none | Vested minus already claimed |
| `get_schedule(id) -> Schedule` | none | Full record |
| `schedule_count() -> u64` | none | Number of schedules ever created |

Timestamps are ledger-time seconds. They must satisfy `start <= cliff <= end` and `start < end`.

Vesting formula, rounded down:

```
now < cliff   ->  0
now >= end    ->  total
otherwise     ->  total * (now - start) / (end - start)
```

Errors: `InvalidAmount=1`, `InvalidSchedule=2`, `ScheduleNotFound=3`, `NothingToClaim=4`,
`NotRevocable=5`, `AlreadyRevoked=6`, `MathOverflow=7`.

## Quick start

```bash
git clone https://github.com/Alimzy/stellar-vesting && cd stellar-vesting
make test          # unit + property tests
make check         # fmt, clippy, tests
make build         # optimized WASM (needs the wasm32v1-none target)
```

Requirements: Rust 1.85 (pinned in `rust-toolchain.toml`; the declared MSRV is 1.84) and, for
deployment, the [Stellar CLI](https://developers.stellar.org/docs/tools/cli).

### Try it on testnet

```bash
./scripts/demo-testnet.sh
```

The script creates funded testnet identities, deploys the contract, creates a schedule on native
XLM, claims, revokes, claims the vested remainder, and writes the contract ID and transaction
links to `docs/testnet-proof.md`.

## Repository layout

```
contracts/vesting/src/
  lib.rs       entrypoints
  math.rs      pure vesting arithmetic (no Env)
  storage.rs   typed storage access and TTL policy
  types.rs     Schedule and DataKey
  events.rs    ScheduleCreated / Claimed / Revoked
  error.rs     Error enum (stable codes)
  test.rs      integration and property tests
docs/          ARCHITECTURE.md, SECURITY-MODEL.md
scripts/       demo-testnet.sh, create-issues.sh
```
